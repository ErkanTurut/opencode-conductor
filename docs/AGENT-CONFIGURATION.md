# Agent configuration

OpenCode V2 owns native agent configuration. Define agents in `.opencode/agents/<id>.md` or under `agents` in `opencode.jsonc`; see the [agent guide](https://opencode.ai/v2/docs/agents/) and [config precedence](https://opencode.ai/v2/docs/config). Markdown body is `system`; use `steps`, `permissions` and `model: provider/model#variant`. Permissions are ordered; the last match wins. Skills are discovered by OpenCode and controlled using `skill` permission rules, not an agent `skills` field.

The plugin supplies packaged Markdown defaults. A model in that Markdown wins over the old `assets/fleet.json` role mapping; the latter is used only for missing models, with a migration warning. An existing host agent is left unchanged by the transform: OpenCode's editor does not report which fields were explicitly configured, so filling individual fields would risk overwriting native intent. This also means packaged defaults are not merged into an existing host agent. Configure all desired fields in native configuration. No files are materialized by default.

`inspectAgentConfigs(definitions, native?)` from `src/register/agents` returns serializable allowlisted fields, `sources` and `warnings`. `native` is an optional map of already-resolved host agent info keyed by ID, not raw JSONC. Sources are `packaged-md`, `native`, `legacy-fleet`, or `absent`. This function does not fetch host state or credentials. Since the host does not expose individual configuration provenance, native values are attributed to the host as a whole and cannot identify the file that contributed them. System text and permission resources may themselves contain sensitive information; callers must apply authorization and redaction before exposing them remotely. Do not pass provider request bodies or credentials.
