# Runtime safety authority

SQLite admission uses a single immediate transaction for run/task state, graph and dependency validation, active write-scope conflicts, bounded attempts, fencing lease, and attempt creation. Both runner and claim tool fail closed when this authority is absent. Completion rechecks task, run, latest attempt, unexpired lease and fencing token in a single transaction. Verification remains independently executed under exact-command shell policy; a missing or malformed required profile does not pass. Exit 124 is recorded as `infrastructure_timeout_or_exit_124`: the shell exit convention cannot distinguish an actual command exit 124 from timeout. Thrown timeout errors use `infrastructure_timeout`.

Task creation and acceptance amendments create immutable rows in `plan_revisions`; existing runs get a legacy snapshot before their first modification. `listPlanRevisions(runId)` returns `{run_id, revision, parent_revision, reason, graph_json, created_at}[]`; `snapshotPlanCAS(runId, expectedRevision, reason)` appends the *current* graph only if the expected revision matches. It is not a graph mutation API. Attempt `plan_revision` and `policy_identity` columns snapshot available ledger identity; null means unavailable, not verified. New revisions may add unrelated tasks while work runs, but they invalidate those attempts under the strict policy below; an actively leased task's acceptance cannot be amended.

These snapshots do not supply authenticated SHA-bound policy/approval, merge execution, evidence freshness against a candidate, or automatic reconciliation of external changes. No merge or push provider is implemented here. Event approval booleans cannot authorize trunk push. A complete merge gate must bind independently verified candidate SHA, plan, policy, checks, findings and human approval, and fail closed when absent. Historical attempts and policy identities cannot be reconstructed by migration. `updateRunPlan` and other legacy mutation paths are not a CAS graph editor and should not be treated as one. Revisions do not automatically verify base ancestry or detect out-of-band database edits. Runtime task admission remains the ultimate dependency and scope gate.

## Binding and workspace limitations

Success is refused if the current persisted policy binding or plan revision differs from admission, or the current graph differs from its recorded snapshot. This deliberately uses **strict invalidation**: even an unrelated sibling revision invalidates running attempts and requires a new attempt. A pre-migration graph is snapshotted at admission. For runs without an effective workflow hash, a `legacy:` digest binds the persisted policy fields and plan text; it detects changes but is **not** a verified policy authority. Pre-migration attempts with null bindings cannot succeed. Raw out-of-band changes to external policy files are not detected by this ledger-only identity; a trusted policy adapter is still required.

Scopes accept repository-relative literal paths and a final `/**`; absolute paths, traversal, backslashes, controls and other glob syntax are refused. Scope collision admission is lexical and checks scope roots for symlinks when the recorded repository identity is an absolute inspectable path. This is not a guarantee against symlink aliases: non-path identities and future workspace changes lack trusted filesystem authority at admission. Before mutating success, both runner and evidence tool independently inspect Git's diff from the bound base plus staged/unstaged and all untracked paths (including ignored paths), require paths within both write and allowed scopes, and reject existing symlink components. Missing workspace/base/diff is a failure. This is not a filesystem sandbox: files outside the worktree, ignored external effects, symlink races, and mutations after the diff check are not monitored; authoritative isolation and a trustworthy quiesced provider are still unsupported. Caller-supplied changed-file lists are not evidence.

Task prompt fields are serialized as untrusted JSON with delimiter escaping and text normalization. This reduces structural delimiter injection, not semantic prompt injection; enforcement remains outside the model. Prompt-displayed verification commands are normalized and whitespace-collapsed; the separately registered original command strings are preserved for independent shell-policy verification.


## Bound workspaces and invalidation recovery

Mutating plugin claims resolve the canonical task workspace from the ledger, independently compare its recorded base with the main checkout HEAD and the workspace HEAD, and verify its canonical branch and Git common directory. Caller-provided workspace IDs cannot substitute another workspace, and caller-provided base SHAs do not select the evidence base. The worktree creation tool rejects a supplied base that differs from the observed main HEAD. Completion rechecks the record, repository, branch and base ancestry; the runner uses the same checks. A missing or uninspectable binding is refused. These Git checks are observations, not an atomic filesystem lock; a hostile concurrent process can race observations, and authenticated/quiesced workspace-provider identity remains unsupported.

Change collection unions base-to-HEAD, base-to-index, index-to-worktree and untracked paths, so staged changes remain visible even when the working copy has been restored to the base. Strict plan/policy invalidation of a still-current attempt atomically fails the attempt and task, records an event, and releases its fenced lease. Retrying requires the normal bounded retry path; stale foreign completions cannot modify the replacement attempt. Other interruptions and parked-run recovery remain governed by the existing watchdog, not this invalidation path.
